1 List of Requirements
1.1 Protocol
PCIE_MAS_REQ_PROTOCOL_101: 支持 PCI Express Base Specification, Revision 5.0, Version 1.0
PCIE_MAS_REQ_PROTOCOL_102: 支持 Gen1, Gen 2, Gen3, Gen4 and Gen5
PCIE_MAS_REQ_PROTOCOL_103: 支持 PIPE 5.1.1, lane 位宽 40bit
1.2 Main Feature
PCIE_MAS_REQ_VC_201: 支持 2 个 VCs, Traffic Classes (TCs) 和 Quality of Service (QOS)
PCIE_MAS_REQ_PF_202: 支持 1 个 PF
PCIE_MAS_REQ_MaxPayloadSize_203: TLP 最大 Payload 256B
1.3 PCIe Reference Clock Mode
PCIE_MAS_REQ_RefClkMode_301: Common Clock (CC) 模式。 EP 从 Host 获取参考时钟
PCIE_MAS_REQ_RefClkMode_302: Separate RefClk Independent SSC(SRIS)/ Separate RefClk No SSC(SRNS) 模式。 EP 从 Host 获取参考时钟
1.4 Performance
PCIE_MAS_REQ_PERFORMANCE_401: PCIe 支持 Round Trip Latency 1us. PCIe DMA 读 / 写达到 80%
PCIE_MAS_REQ_PERFORMANCE_402: PCIe 支持 Round Trip Latency 1us. PCIe IB 读 / 写性能达到 80%
PCIE_MAS_REQ_PERFORMANCE_403: PCIe 支持 Round Trip Latency 1us. PCIe OB 读 / 写性能达到 80%
1.5 AXI
PCIE_MAS_REQ_AXI_SlAVE_501: OB 方向 AXI4 Slave 数据位宽 512Bit, 地址位宽 48Bit. 外接 Main NoC 完成 OB 方向的数据传递
PCIE_MAS_REQ_AXI_SLAVE_502: OB 方向 AXI4 Slave 最大 AXI length 4 ，最大 AXI Size 64B ，最大 Burst Size 是 256B
PCIE_MAS_REQ_AXI_SLAVE_503: OB 方向 AXI4 Slave 支持 Non Contiguous Byte Enable(NCBE),OB 方 向可以支持发 MWr 类型的 NCBE 。
PCIE_MAS_REQ_AXI_SLAVE_504: OB 方向 AXI4 Slave 通过将 WSTRB 位置 0 支持 Zero byte length 写 访问
PCIE_MAS_REQ_AXI_SLAVE_505: PCIe AXI OB 方向支持 INCR 和 WRAP 类型访问
PCIE_MAS_REQ_AXI_SLAVE_506: OB 方向 AXI4 Slave 支持 256 Tags
PCIE_MAS_REQ_AXI_SLAVE_507: OB 方向 AXI4 Slave 支持 W channel 早于 AW channel
PCIE_MAS_REQ_AXI_MASTER_508: IB 方向 AXI4 Master 数据位宽 512Bit, 地址位宽 48Bit, 负责将 IB 和 DMA 数据访问传递给 Main NoC
PCIE_MAS_REQ_AXI_MASTER_509: IB 方向 AXI4 Master 单笔访问 length 最大 4,Size 最大 64B, Burst 最大是 256B

1.20 Isolation
PCIE_MAS_REQ_ISO_2001: PCIe DFT 支持 pcie_core 的 partial good
PCIE_MAS_REQ_ISO_2002: PCIe 支持 partial good, 在 PCIe 子系统的顶层实现 isolation 。 SoC 有 isolation enable 寄存器控制，默认是 1. 需要保证能正常开关，在 isolation disable 的时候能够正常工 作。
PCIE_MAS_REQ_ISO_2003: PCIe 的 partial Good 的 Isolation 需要保证在 isolation 状态 AXI slave 在 NoC 发起访问不 hang 死， AXI Master 不主动发起对 NoC 的访问，配置总线在 SoC 发起访问配置空间 访问不 hang 死。
Note ：确认在 PCIe isolation 情况下。 PCIe 的 MainNoC AXI 无时钟不影响除 PCIe 数据接口外的数据通 路正常工作， MainNoC Soft reset 受限。 AXI 有 20MHz 时除 PCIe 数据接口外的数据通路正常工作且可以正 常完成 Soft Reset(550 MainNoC 无 soft reset 需求 ) 。
PCIE_MAS_REQ_ISO_2004: PCIe 子系统有 TSV 直穿，在进入 BD 的 port 上有 Isolation 和 level shifter ，默认是 isolation 是 enable 状态，控制寄存器在 PCIe 子系统软件可配。需要保证 isolation 正常 开关， TSV 信号在 isolation 具体参考 SoC MAS SOC_MAS_REQ_BD 的相关介绍。
PCIE_MAS_REQ_DISABLE_2005: PCIe 需要 PHY 和 controller 能够 disable 。 PHY 需要 PCB 保证 PHY 不工作是正常断电， controller 可以 isolation 。

4.5.2 硬复位描述
硬件冷复位 power_on_rst_n ，整个芯片通过外部 PAD 控制复位。冷复位会导致 PCIe 设备重新初始化，恢复 到初始状态。
暖复位， Host 通过拉低边带信号 PERST# 对 PCIe 进行复。芯片需要将 PERST# 直接接到硬件冷复位 power_on_rst_n 对全芯片进行复位。整个芯片包括 PCIe 需要在 PERST# 复位以后重新启动建连。
4.5.3 Hot Reset
PCIe 接收上游设备 (RC/Switch) 发起的连续 2 个带热复位为 1 的 TS1 Order Set ，对应 TS1 携带的 link 和 lane 将会进入 Hot Reset 状态。 PCIe 子系统收到 Hot Reset 回向 SoC 发出 Hot Reset 标志开始对未完成访问进行 flush 。 Hot Reset 控制器时序参考 PCIe Controller Databook 的' 2.4.3 Hot Reset '章节。

为了保证 Hot Reset 顺利完成在 PCIe 子系统和 SoC 添加了 Hot Reset 控制逻辑。具体实现参考了文档 [1] ' Hot Reset '章节时序图。
4.5.3.1 Outbound AXI blocking
在 PCIe 控制器接收到 Hot Reset 指令以后，会产生 Hot Reset 标志输出到给 HotResetBlock 模块。为了防止 SoC 对 AXI Slave 的不间断访问影响 PCIe 的 Flush ，导致 Flush 不能结束。 HotResetBlock 在接收到 Hot Reset 标志以后主动管理 AXI Slave 访问。
HotResetBlock 保证 PCIe 控制器已接收的 AXI 访问正常完成，主动截获新的 AXI 访问阻止新访问到达 PCIe 控制器，保证 PCIe 控制器能够正常 flush 完成。
另因为 HotResetBlock 不能主动退出 Hot Reset 状态， SoC 在进行 Hot Reset 期间需要对 HotResetBlock 模块 进行 Reset 以此保证模块可以正常退出 Hot Reset 状态。
4.5.3.2 Hot Reset Flush timer
在收到 PCIe Hot Reset 标志后激活 PCIe 的 Flush Timer ，拉低 PCIe 的 LTSSM 使能信号，等待 timer 计时完 成以后重新使能 LTSSM 。通过 timer 计时方式延长 PCIe 控制器的 flush 时间，方便调整 PCIe 的 flush 时间。 Flush Timer 的 timeout 时间从 0 到 134ms 可控。
4.5.3.3 Hot Reset LTSSM Enable Disable
在 PCIe 控制器 flush 完成并发出给 SoC Hot Reset 标志同时，会主动拉低 LTSSM 的使能信号。等待 SoC 的 Reset 完成可重新配置 PCIe 并主动使能 LTSSM 状态机建连。
4.5.3.4 SoC Hot Reset 控制
SoC 的 CPU 收到 PCIe flush done 中断以后，触发 watchdog timer ，在 time timeout 时触发 Reset 对 SoC 进 行 reset( 包括 PCIe 子系统内部的 HotResetBlock 以及 TBU) ， SoC Reset 完成重新进行 boot(PCIe 除外 ) 。 SoC boot 完成以后开始配置 PCIe 的 LTSSM Enable 重新进行 link training 建连。

4.15 UPCS PIPE 介绍
4.15.1 UPCS 结构
UPCS PIPE 的子系统包含 1 个 x16 的 UPCS 和 4 个 x4 的 PHY 。共同组成 UPCS PIPE 子系统。 UPCS 和 PCIe 控制器之间通过 PIPE 接口相连。
4.15.2 PIPE 接口
UPCS 支持 SerDes PIPE 或 Original PIPE, UPCS 的 PIPE 接口采用的是 SerDes PIPE 结构。
SerDes PIPE 接口和 PHY 的 parallel 数据接口都采用单个 40bit 的数据结构。 PHY 的 PIPE 接口细节可参考文 档 4.7.
4.15.3 时钟源
PHY 的外部参考时钟情况， 4 个 PHY 独立差分参考时钟输入，在 4 对差分参考时钟输入需要再 PAD 端连同一 个时钟源。
或板级提供 1 个 PHY 时钟源，板级时钟源从 PHY0 的 pad_ref_clk_n/m 输入， PHY1 的参考时钟从 PHY0 的 ref_repeat_clk_p/m 输入，依次类推。
PCIe 子系统会生成 lock_phy_ref_clk 给到 PHY 作为参考时钟，作为调试手段备用。
4.15.4 时钟输出
UPCS 的 16 个 lane 每个 lane 都有 1GHz 的 max_pclk 输出， max_pclk 用于生成 core_clk 作为 controller 的 主要逻辑时钟和同时生成 pipe_pclk 作为 PIPE TX 的接口时钟。
UCPS 同时输出根据 RX 数据流恢复的 pipe_rx_clk 时钟输出给 Controller 的 PIPE RX 方向作为 PIPE 的逻辑时 钟使用。

4.19 Partial good
PCIe 内部实现 partial good 逻辑，在测试发现 PCIe 的 partial good 域的逻辑单元问题可以通过 isolation 方式 disable partial good 域的逻辑。
Partial good 域范围是整个 pcie_core 的功能单元 . CFG NoC, Hotreset, pcie_atc 和 pcie_crg 不在 partial good 域。
Isolation 需要保证 MainNoC 对 PCIe 的 AXI slave 的访问不夯死。在 PCIe isolation 的时候不能影响 MainNoC 的正常工作。
